# Ошибки
**Основы PHP**

## Общая информация

Если программа на PHP написана синтаксически некорректно, то интерпретатор выводит на экран сообщение об ошибке, а также указывает **файл и строку**, где, по его мнению, произошла ошибка.

Например, синтаксическая ошибка возникает, когда код записан с нарушением грамматических правил.  
В человеческих языках текст с ошибками можно понять, но в программировании всё гораздо строже — **даже одна пропущенная точка с запятой приведёт к сбою**.

Пример:

```php
<?php

print_r('Hodor')
// PHP Parse error:  syntax error, unexpected end of file in /private/var/tmp/index.php on line 4
```

Такие ошибки называются **Parse error**.  
Они самые простые, потому что связаны не со смыслом кода, а с нарушением синтаксиса.

Однако интерпретатор не всегда точно указывает на строку, где ошибка произошла — например, забытая скобка может находиться раньше.

---

## Уведомления и предупреждения

Исторически в PHP существует **особая система ошибок**, отличающаяся от других языков.

В большинстве языков программирования ошибки делятся на два типа:

1. **Ошибки парсинга**  
2. **Исключения (exceptions)**

В PHP же добавлены дополнительные категории:

- **Notice**  
- **Warning**  
- **Fatal Error**

---

### 🔹 Notice

Пример:

```php
<?php

$i += 3;
// PHP Notice:  Undefined variable: i in php shell code on line 1
```

`Notice` — это не ошибка, а **предупреждение**, что код написан плохо, но выполнение программы не останавливается.  
Во многих других языках подобное вызвало бы исключение.

---

### 🔹 Warning

`Warning` — это тоже предупреждение, но **более серьёзное**.  
Оно сообщает о потенциально опасной ситуации, однако программа продолжает работать.

---

### 🔹 Fatal Error

`Fatal Error` — это настоящая ошибка, которая **завершает выполнение программы**.  
Она не может быть обработана как исключение и прерывает выполнение скрипта.

---

## Подавление ошибок

PHP позволяет **подавлять предупреждения**, что считается плохой практикой.

Полное отключение сообщений:

```php
<?php
error_reporting(0);
```

Подавление только в конкретной строке:

```php
<?php
function foo()
{
    $i += 1;
}

foo(); // Notice: Undefined variable: i
@foo(); // Ничего не выводится
```

Оператор `@` подавляет все `Notice` и `Warning`, происходящие внутри вызова функции.  
Использовать его **не рекомендуется**, так как это скрывает реальные ошибки.

---

## Правильный подход

Все предупреждения нужно рассматривать как **серьёзные ошибки**, требующие исправления.  

На платформе **Хекслет** система настроена так, что все `Notice` и `Warning` автоматически **превращаются в исключения**, благодаря настройкам `xdebug`.
