# Включение файлов
**Основы PHP**

## Зачем нужно включение файлов

Сайты и программы на PHP часто содержат **десятки тысяч строк кода**, поэтому код необходимо **разбивать на отдельные файлы**.  
Для этого в PHP существует механизм **включения файлов**, реализованный через четыре конструкции:

- `include`
- `include_once`
- `require`
- `require_once`

---

## Конструкция `require_once`

```php
<?php
// file: print.php

function sayHi()
{
    print_r('Hi!');
}

// file: index.php
require_once 'print.php';

sayHi(); // => Hi!
```
После включения файла `print.php`, функция `sayHi()` становится доступной в `index.php`.

---

### Доступ к переменным из подключённого файла

```php
<?php
// file: print.php
$x = 'Hi!';

// file: index.php
require_once 'print.php';
print_r($x); // => Hi!
```

При подключении файл **выполняется**, а все его переменные и функции становятся доступны в основном файле.

---

## Порядок выполнения

```php
<?php
// file: print.php
print_r("Hi from print.php!\n");

// file: index.php
require_once 'print.php';
print_r("Hi from index.php!\n");
```

Результат выполнения:

```
Hi from print.php!
Hi from index.php!
```

То есть PHP **сначала выполняет код** подключаемого файла, а затем — остальной код.  
Фактически `require_once` как будто **вставляет содержимое файла** в место вызова.

---

## Вложенные подключения

Если во включаемом файле есть другие подключения, они тоже выполняются.  
Таким образом, весь код проекта доступен внутри одного пространства.

---

## Почему стоит использовать только `require_once`

Конструкция `require_once` обладает двумя ключевыми преимуществами:

1. **Если файл отсутствует** — выполнение программы прекращается с ошибкой.  
2. **Если файл уже подключён** — он не подключается повторно (во избежание дублирования).

---

### Различия между конструкциями

| Конструкция | Ошибка при отсутствии файла | Повторное выполнение |
|--------------|------------------------------|------------------------|
| `require_once` | Да | Нет |
| `require` | Да | Да |
| `include_once` | Нет | Нет |
| `include` | Нет | Да |

---

## На практике

В современных проектах явное подключение файлов **не используется**.  
Эту задачу выполняет **Composer** — менеджер зависимостей, который реализует **автозагрузку классов и функций**.
