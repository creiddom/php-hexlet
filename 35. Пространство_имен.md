# Пространство имен
**Основы PHP**

## Зачем нужны пространства имен

Если попытаться определить две функции с одинаковыми именами, PHP выдаст ошибку во время запуска:

```php
<?php
function foo()
{
    print_r('one');
}

function foo()
{
    print_r('two');
}

// PHP Fatal error:  Cannot redeclare foo()
```
Ошибка возникает, потому что **нельзя переопределить уже существующую функцию**.

---

## Проблема коллизий имен

Реальные приложения на PHP содержат тысячи строк кода и часто используют внешние библиотеки.  
Если две библиотеки определяют функции с одинаковыми именами, возникает **конфликт (коллизия)**.

Раньше разработчики избегали этого, добавляя к именам функций префиксы:

```
mylibnameSendEmail()
mylibnameAddNewUser()
```

Это делало код громоздким и не решало проблему в корне.

---

## Решение — пространства имен

С версии **PHP 5.3** появился механизм **пространств имен (namespaces)**.  
Они обеспечивают изоляцию кода разных файлов и предотвращают коллизии.

Пространства имен можно сравнить с:

- 📁 **Директориями** в файловой системе  
- 📞 **Кодами стран** в номерах телефонов  
- 🏙️ **Городами и улицами** в адресах  

В них можно создавать **вложенные структуры**, например:

```
App ├── Math │    └── sum()
 └── Text      └── multiply()
```

---

## Объявление пространства имен

```php
<?php
// math.php
namespace math;

function sum($a, $b)
{
    return $a + $b;
}
```

Теперь вызвать функцию можно только с указанием полного пути:

```php
<?php
require_once 'math.php';

\math\sum(5, 8); // 13
```

Если попытаться вызвать `sum()` без указания пространства имен — PHP вернет ошибку *undefined function*.

---

## Использование нескольких пространств имен

```php
<?php
// text.php
namespace text;

function multiply($word, $times)
{
    return str_repeat($word, $times);
}

// number.php
namespace number;

function multiply($a, $b)
{
    return $a * $b;
}

// index.php
require_once 'text.php';
require_once 'number.php';

	ext\multiply('hi', 3); // hihihi

umber\multiply(3, 2);  // 6
```

Теперь можно определять одноименные функции в разных пространствах без конфликтов.

---

## Вложенные пространства имен

```php
<?php
// main.php
require_once 'text.php';
require_once 'number.php';

namespace main;

function multiply($a, $b)
{
    print_r('it works!');
}

function all()
{
    	ext\multiply('ho', 2); // hoho
    
umber\multiply(3, 2);  // 6

    // Текущая область видимости — \main    multiply(2, 3); // it works!
}
```
Функции внутри одного пространства имен могут **взаимодействовать напрямую**, без префикса.

---

## Итог

Пространства имен решают проблему дублирования имен, обеспечивая:

- изоляцию кода;
- читаемость и структуру;
- возможность использования сторонних библиотек без конфликтов.

## Заметка
### PHP: Импорт с use и Псевдонимы as
1. `use` как "Ярлык"
Оператор `use` создает короткий "ярлык" (псевдоним) для длинного имени класса, функции или константы из другого namespace (пространства имен). Это позволяет не писать полный путь каждый раз.
Вместо того чтобы писать:


```php
<?php
namespace App;

$result = \Strings\reverse('hello');
$result2 = \Strings\reverse('world');
```
Можно сделать так:

```php
<?php
namespace App;

// Импортируем функцию в текущую область
use function Strings\reverse;

// Теперь можно вызывать ее по короткому имени
$result = reverse('hello');
$result2 = reverse('world');
```

2. Проблема: Коллизия (Конфликт) Имен. Проблема возникает, если вы пытаетесь импортировать имя, которое уже используется в вашем текущем namespace.
Пример: Вы в namespace **App** и у вас есть своя функция `reverse()`. Вы не можете импортировать чужую функцию `Strings\reverse` под тем же именем `reverse`.

```PHP
<?php
namespace App;

// Пытаемся импортировать \Strings\reverse
// под коротким именем 'reverse'
use function Strings\reverse;

// НО! У нас уже есть СВОЯ функция 'reverse'
function reverse($arr)
{
    // ... какой-то код ...
}

// PHP выдаст ФАТАЛЬНУЮ ОШИБКУ:
// "Fatal error: Cannot use function Strings\reverse as 'reverse' 
// because the name is already in use"
```
3. Решение: Псевдоним `as`. Ключевое слово as позволяет импортировать имя, но дать ему другой (локальный) "ярлык", чтобы избежать конфликта.
Это как сказать: 
>"Импортируй \Strings\reverse, но здесь я буду называть ее stringReverse".

```PHP
<?php
namespace App;

// Импортируем \Strings\reverse,
// но будем называть ее 'stringReverse'
use function Strings\reverse as stringReverse;

// Это НАША функция (App\reverse)
function reverse($arr)
{
    return array_reverse($arr);
}

// Вызываем НАШУ функцию
$myArray = reverse([1, 2, 3]);

// Вызываем ИМПОРТИРОВАННУЮ функцию по ее псевдониму
$myString = stringReverse('hello');
Теперь коллизии нет. Внутри namespace App у вас есть:

reverse (ваша функция)

stringReverse (ярлык для \Strings\reverse)
```
